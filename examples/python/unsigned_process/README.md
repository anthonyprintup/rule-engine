# Unsigned-process Python pack

This source-only example declares one typed process rule. The C++ compiler treats
the decorator, model, identity fields, data label, and provider route as static
declarations; it never executes this module as Python.

The pack intentionally has no checked-in index, signature, generated bytecode,
or private runtime. `rule_engine_pack build` creates a canonical `.rpack`, and
production activation additionally requires an Ed25519 signature from an
operator-authorized key. Unsigned output is accepted only under an explicit
development trust policy.

```powershell
rule_engine_pack build --source . --output unsigned-process.rpack
rule_engine_check --pack unsigned-process.rpack --trust-mode development
```

The Windows provider returns the typed `process.signer.is_signed` fact. The
server-side C++ VM alone evaluates `not process.is_signed` and decides whether
the rule matches.
