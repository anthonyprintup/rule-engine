# Python Engine Implementation Status

This document separates implemented, verified behavior from the target architecture in this directory. The architecture remains normative design intent; a capability is available only when it appears below with code and test evidence. Exact host, command, artifact, and pass/fail evidence is recorded in [QUALIFICATION.md](QUALIFICATION.md).

## Implemented and locally verified

- Shared C++23 contracts for budgets, typed recursive subjects, facts, scans, bytecode, VM suspension, effects, events, state, protocol, storage, activation, and policy.
- Canonical source-only pack loading, bounded archive validation, SHA-256 identities, OpenSSL 3 Ed25519 verification, and production rejection of unsigned or policy-invalid packs.
- Exact CPython 3.14.6 worker staging/validation, isolated parse/generate framing, and Windows Job Object limits for wall time, CPU, memory, output, handles, and descendant processes. Static rule modules are parsed as data and are not imported or executed.
- A static Python compiler and verified register VM covering the implemented language subset, including real worker-AST to compiler to VM interoperability, deterministic fact/capability operands, fresh list/tuple/dictionary values, schema-typed event records, bounded synchronous iteration, closed typed exception handlers, `else`/`finally` cleanup, state transactions, generator controls, bounded recovery, and exact operator behavior.
- Transactional effect and typed event-intent journals, label propagation, recorder/replay support, typed services, durable outbox/event projection, typed events/history/state, MVCC retry, migrations, and fenced correlation primitives.
- Protocol-v2 bounded codecs, TLS 1.3 mutual authentication, durable SQLite WAL agent spooling, lossless typed scan messages, and snapshot/session validation.
- Real RE2-backed literal, masked-byte, UTF-8/UTF-16, and regex scans over explicit spaces with bounded context, multi-pattern attribution, exact/existential modes, and deterministic zero-length handling.
- Durable Windows SQLite runtime storage with atomic receipts, cursors, state, history, journals, outbox, leases, and fencing. A guarded PostgreSQL implementation is present and warning-clean at compile time.
- Agent durable ingress uses the same runtime store authority. The body and cumulative `(tenant, peer, epoch)` receipt commit in one transaction guarded by the current session lease; exact retries are idempotent, gaps and changed replays are rejected, and stale sessions cannot advance the receipt. SQLite restart tests and the in-memory crash-before-commit injection prove that an ACK is never earned by a partial write.
- Backend-neutral resident orchestration with captured-input replay, original-plus-two MVCC attempts, mandatory fail-closed VM usage snapshots, cumulative remaining-budget profiles, stale-fence rejection, cancellation, and atomic event/state/effect/outbox proposals.
- Concrete runtime adapters bind protocol-v2 fact/scan responses to exact work leases, require exact requested/returned schema ID/hash equality for fact values, reject malformed terminal unions and stale or conflicting sequence/generation/fence data, advance durable sequence state only after persistence, commit through the fenced coordinator, and keep replay dispatch-free.
- Versioned PEP 561 authoring stubs and a fail-closed author runtime plus a deterministic trusted-generator SDK, validated under the exact private CPython runtime and qualified with strict Pyright 1.1.411 and Ruff 0.15.22 checks.
- Text, JSON, and SARIF command models for pack/check/admin workflows, source diagnostics, watch-generation cancellation, redaction, and conservative mutation previews.
- Typed Windows process, image, PE, signer, memory, and scan providers use recursive subject identities and return only facts or scan observations. An authoritative route catalog binds each fact to a value schema ID/hash; the provider rejects request/catalog drift and attests that identity only on a structurally matching value. The provider suite includes process-incarnation and generation validation, deadline/error mapping, PE parsing bounds, signer policy, and scan-space tests.
- The production Windows `rule_engine_agent` has deterministic `--help`/`--version`, exact `--config PATH` plus optional trailing `--validate-config`, and a strict schema-v2 bounded configuration for absolute spool/credential/optional CRL paths, numeric failover endpoints, TLS DNS name, exact URI SAN and SHA-256 fingerprint, peer identity, active generation, inventory cadence, and mandatory hard resolver bounds. Explicit local-CRL enablement uses OpenSSL full-chain checking and fails closed on missing, malformed, stale, wrong-issuer, or revoked material.
- The agent composes TLS 1.3 mutual authentication with persistent SQLite epoch/sequence spooling, hello/lease/cancel/ACK/NACK/credit handling, bounded reconnect/replay, pending-result deduplication, and atomic authoritative snapshot batches. It publishes process inventory immediately and on a mandatory validated 1-second-to-24-hour cadence without overlapping enumeration. Results and complete snapshot batches are durable before their first send; failed or partial enumeration emits nothing and retains server-side last-good authority.
- Agent work is dispatched only through `WindowsAgentProviderRuntime` fact, scan, and process-inventory entry points. Its transport/provider seams contain no predicate, rule, bytecode, or verdict field; stale sessions/fences/generations, unknown messages/config keys, oversized future deadlines, missing backends, and invalid provider projections fail closed.
- Focused fake-session and provider tests cover strict config/CLI rejection, whole-snapshot durability, periodic complete refresh, last-good preservation after enumeration failure, monotonic spool-derived inventory generations, reconnect replay without duplicate dispatch, duplicate leases, cancellation, transient NACK retry, cumulative ACK, stale fences, the facts-only boundary, and `BUILD_TESTING=OFF`. `rule_engine_python_agent` installs/exports through the central package graph with the installed executable name `rule_engine_agent`.
- The resident server owns a fixed `std::jthread` service pool, bounded admission queue, explicit application-memory reservation, per-session frame/message/work/deadline limits, cancellation-aware join, and TLS-only production agent/admin application paths. Agent sessions negotiate protocol v2, validate exact lease/result identities through the runtime adapter, and emit cumulative ACK only after an injected backend reports the body and receipt durable. Admin sessions use a separate canonical bounded binary codec and route pack/operation reads plus activation flip through `AuthorizedActivationAdmin`.
- Byte-faithful fake-channel tests cover hello/work/result/ACK bytes, malformed admin frames, stale inner fences, denial before any activation-store read or mutation, queue overload, and joined shutdown. Production configuration requires every worker, queue, memory, frame, session, work, and credit bound explicitly.
- Resident startup resolves each durable active generation to one content-addressed signed archive, verifies it under the configured trust snapshot, compiles it with the pinned private worker and C++ compiler, and compares the resulting source, compiler ABI, semantic, binding, and executable identities with the finalized activation evidence. A mismatch fails readiness before a listener starts.
- The resident evaluator rebuilds committed authoritative snapshots from durable agent ingress, projects each matching subject/binding pair into deterministic generation-fenced work, resumes fact and scan results in the C++ VM, and commits the projected state, history, effects, events, outbox, usage, and receipt through the fenced coordinator. Focused restart tests prove that committed snapshot input reconstructs pending work without moving predicates or verdicts onto the agent.
- Agent hello negotiation now advertises the exact schemas and capabilities required by the active compiled packs. Sessions lacking a required schema ID, major version, descriptor hash, or capability are rejected before work is issued.
- The authenticated resident admin v5 request wire and standalone mTLS client expose pack/operation reads, verified resumable upload, bounded durable-operation polling, server-owned stage and rollback preview/apply, and the explicit activation preview, drain, straggler-fence, and atomic-flip sequence. A stage accepts only a published source digest and state identity, freezes exact leased resident targets, and is finalized only from server-generated reports whose semantic and binding hashes agree. Rollback selects retained source and a new monotonically increasing generation, reconstructs the request on the server, recompiles it everywhere, and additionally requires the retained semantic/binding identities.
- Every stage now carries an immutable `activation-policy.v1` snapshot. Its SHA-256 bundle identity covers the exact configured signer, revocation, peer-enrollment, operator-binding, resident-capability, schema, budget, retention, trace, capture, service, and sink files. The identity is part of the idempotency fingerprint and durable generation evidence. A resident will not compile, report, or serve a generation whose snapshot differs from the policy bundle it loaded at startup.
- Server configuration schema v3 requires explicit global and tenant registry quotas, abandoned-upload TTL, unreferenced-object retention, and a versioned resident-capability inventory. Upload identities and durable metadata are tenant-scoped; exact retry bytes are durably appended; reservations account conservatively against both quotas; and fixed session/completion caps bound metadata growth. Startup and periodic maintenance derive reachability from every durable generation phase, preserve referenced source, expire abandoned partials, and collect only aged unreferenced uploaded objects.
- Each resident publishes its sorted, duplicate-free `rule-engine.resident-capabilities.v1` inventory under the current node-lease fence. Server-owned stage selects only current serving nodes that advertise every signed-pack requirement, persists the exact inventory in target evidence, and fails without a generation when no node qualifies.
- Each resident maintains fenced node evidence, resumes unfinished compilation from durable control state, recompiles its target locally with the exact private worker, and reports platform-specific executable evidence. After an atomic flip, every resident detects the changed durable active identity, fences old sessions, recompiles and verifies the active source, and swaps schedulers only after those sessions reconnect.

## Security boundary

The worker controls protect service availability and prevent accidental ambient Python use; they are not a hostile-code sandbox. Static rule source is never executed by CPython. A generator executes only after pack signature and signer policy authorize it, and the generated proposal is validated and double-run for operational determinism. A malicious authorized generator remains inside the trusted signer boundary described by L-001.

Agents do not receive predicates, rule bytecode, or match decisions. They receive typed fact and scan requests and return authenticated observations. C++ remains responsible for validation, scheduling, optimization, replay, effects, persistence, and the final outcome.

## Known implementation and qualification gaps

- The compiler/VM do not yet implement every construct described by the target subset. Current gaps include complete iterator/container lowering, comprehensions and generator expressions, nested generator/coroutine object creation, `yield from`, general async task bytecode, keyword/default/variadic binding, full pattern matching rollback, arbitrary/user exception classes, handler binding, exception causes/groups, bare re-raise from finalizers, and complete model/class semantics. State authoring currently supports module-level scalar `StateKey` declarations with peer or subject scope and `get`/`set`/`delete` in reportable entrypoints. Records, non-`None` defaults, wider scopes and classifications, explicit identities, compare-and-set/require, helper ownership, shared state, and migrations remain closed. The implemented closed exception subset and its rationale are recorded in [L-028](LIMITATIONS.md#l-028--the-exception-frontend-is-intentionally-closed); the exact state boundary is recorded in [L-026](LIMITATIONS.md#l-026--container-and-iteration-frontend-is-intentionally-partial).
- The VM currently materializes the entry subject through fact requests rather than a complete author-visible subject object. Some handler metadata and decisions remain convention-based because the frozen bytecode contract lacks structured fields for them.
- Typed custom-event payloads now cross exact `@schema`/`EventRecord` analysis, explicit `wire_field` IDs, keyword-only construction with statically canonical scalar defaults, standalone `telemetry.emit(record)` lowering, the verified VM, server projection, durable result codec, retry/replay, and atomic store commit. Complete envelope metadata, dynamic or aggregate constructor defaults, in-rule receipt materialization, and pre-marker result migration remain [L-030](LIMITATIONS.md#l-030--custom-event-envelope-metadata-and-author-conveniences-are-partial). `balanced.v1` has no separate cumulative logical-allocation ceiling; cross-retry allocation usage is reported and overflow-safely aggregated under [L-029](LIMITATIONS.md#l-029--logical-allocation-has-no-distinct-balancedv1-ceiling).
- Production agent dialing, identity pinning, local-CRL enforcement, reconnect, durable replay, and the server's owned bounded listener scheduler are implemented. Authenticated idle sessions poll ready work at a validated 10 ms-or-greater operator interval without adding a second channel writer and remain bounded by negotiated bytes/work plus the session lifetime. The application service exposes a coherent, concurrency-safe, saturating, payload-free snapshot of empty/nonempty polls, delivered leases, and observed idle-to-send delay count/total/maximum. This is per-session polling rather than a database notification fabric; the snapshot is process-local and has no Prometheus/OTLP exporter or durable histogram. OCSP, online CRL fetching, live CRL reload, and every SQLite crash boundary remain unqualified.
- PostgreSQL 17 was unavailable on the implementation host. The driver-enabled branch was warning-clean compiled against the API surface, but real libpq linking, migrations, TLS connections, concurrency, failover, cancellation, and pooling remain unqualified. The current adapter owns one mutexed connection.
- Runtime and activation state have durable SQLite/PostgreSQL adapters, and the production session backend now grants bounded durable-message credit backed by the atomic agent-ingress transaction and resident evaluator. The evaluator supports agent fact/scan turns plus server-local durable state reads and atomic writes for verified bytecode. The Python frontend emits that bytecode for the narrow scalar peer/subject subset above, and the resident evaluator additionally folds peer or canonical subject identity into the opaque physical namespace. State is partitioned by tenant, pack, activation-selected namespace, logical namespace, executable owner, and declared scope before it reaches the store. The compiler hashes every state declaration, including unused keys, into one canonical SHA-256 state-schema identity. Server-owned stage preview derives the durable identity with the pinned worker; every resident recompiles the source, and startup requires its state identity plus semantic, binding, and executable evidence to match the active generation. A resident state conflict now creates a fresh verified VM at most twice, rereads server state, reuses exact captured fact/scan responses without agent redispatch, and inherits only the remaining cumulative normal budget. Replay divergence and exhausted retries fail closed. If the process stops after accepting a provider result but before VM commit, a same-node restart reconstructs bounded contiguous durable provider rounds, reacquires its still-current lease, validates them through a fresh VM, and commits without redispatch. Cross-node takeover still waits for lease expiry, and VM frames/resource counters are not checkpointed. Capability/service/history turns, migration execution, multi-route suspended turns, and full durable VM checkpoints remain incomplete; see [L-026](LIMITATIONS.md#l-026--container-and-iteration-frontend-is-intentionally-partial), [L-031](LIMITATIONS.md#l-031--resident-host-services-and-retry-are-partial), and [L-033](LIMITATIONS.md#l-033--filesystem-and-administration-adapters-are-intentionally-narrow).
- Rollback currently exposes only schema-compatible state carry. Migration, reset, and retained-gap state handling remain incomplete. Successful source-registry maintenance now atomically retains a bounded aggregate and the latest 32 aggregate-only audit records; authorized pack reads expose cumulative expiry/reclamation counters and the last-success timestamp without source content, digests, identities, or paths. A Prometheus series and remote object-store adapter remain incomplete. Online policy mutation is intentionally excluded: policy files are deployment-owned immutable inputs changed through controlled restart and restage, not admin-managed live records. Unsupported operations fail closed rather than accepting client-supplied compilation evidence or silently broadening a target set.
- Windows private-runtime installation, the complete six-executable package graph, relocation/downstream install smoke tests, strict author-SDK checks, deterministic fuzz regression, a 20,000-run ASan/libFuzzer session, and the 10,000-peer in-memory stability model are locally qualified. Linux builds, a Linux private-runtime bundle, live PostgreSQL 17, mixed-OS operation, multi-process crash injection, and production network/database scale remain unqualified; see [QUALIFICATION.md](QUALIFICATION.md).
- Production-agent limitations remain numeric-only endpoints ([L-022](LIMITATIONS.md#l-022--the-production-windows-agent-accepts-numeric-server-endpoints-only)), serialized in-flight cancellation ([L-023](LIMITATIONS.md#l-023--provider-dispatch-cannot-consume-a-later-cancel-frame-concurrently)), fixed-cadence inventory without fleet jitter ([L-024](LIMITATIONS.md#l-024--process-inventory-refresh-uses-a-fixed-per-agent-cadence)), and no online certificate revocation check ([L-025](LIMITATIONS.md#l-025--agent-certificate-revocation-is-not-checked-online)).
- Provider schema attestation is exact at the top-level descriptor, but recursive list/map element descriptors and generated provider-catalog integration remain partial ([L-027](LIMITATIONS.md#l-027--provider-container-schemas-and-catalog-generation-are-partial)).
- Regex match and context contents cannot be independently recomputed by a server that intentionally does not possess the scanned source. The server validates authenticated attribution, identities, permissions, bounds, lengths, pattern membership, and framing; the provider remains the source of fact truth.
- Complete Unicode NFC/case-fold path normalization, locked-wheel dependency materialization, and cryptographic authentication of internal deterministic VM digests remain future hardening work.

## Cutover status

The working cutover removes the former parser/compiler/runtime/protocol source,
Rust bridge, Cargo/cbindgen files, YARA fixtures, legacy tools, and obsolete
documentation from the active build. On 2026-07-21, clean Windows Debug builds
passed 37/37 tests under both clang-cl 22.1.4 and MSVC 19.50.35729. A fresh
disconnected clang-cl Release build with `BUILD_TESTING=OFF` completed 372 build
steps, installed the complete package with its manifest-validated private
CPython runtime, and passed `--version` and `--help` smoke checks for all six
public executables. The exact CPython 3.14.6 archive hash, staged DLL hash,
SDK checks, 20,000-run fuzzer result, and 10,000-peer counters are preserved in
[QUALIFICATION.md](QUALIFICATION.md).

This proves the Windows source/build/package removal gate for the current
integration snapshot; it does not complete the architecture's release gate.
Remaining author-language lowering, host-port and live-activation scheduling,
admin wire/client operations, Linux and mixed-OS cells, live PostgreSQL, and
real multi-process/network fault and scale tests remain open and must not be
inferred from the green Windows-local evidence.
